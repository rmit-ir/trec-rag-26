# Understanding Your RAG Results

For the team's scores, human preference results, and conclusions with report
context, see [SCORES.md](SCORES.md).

Your team folder contains **tab-separated (TSV)** files for your team's runs
only. Open them in a spreadsheet using **Tab** as the separator.
Filter `narrative-id` to **`all`** for
one summary row per run; other rows show individual narratives. `narrative-id` is
the narrative ID, `group` is your team, and `run` is your submission ID.

We evaluate RAG answers using **human pairwise preferences** and
**LLM judgments of how well answers satisfy rubric criteria and cover expected
nuggets**. The rubrics and nuggets are human-authored, with a separate
evaluation using automatically generated nuggets.

Batch 1 and Batch 2 refer to two variants of NIST's human side-by-side
assessment process. In Batch 1, assessors constructed rubrics based on the
topic statement and their own intuition and then performed pairwise preference
comparisons between system responses. In Batch 2, assessors performed nuggetization
(extracting evidence snippets/nuggets from corpus shards), then used these
nuggets as rubrics for pairwise comparisons.

## Side-by-Side Evaluation: Human Preferences

Side-by-side evaluation judges which of two generated answers is preferred by
a human assessor. We fit Bradley–Terry (BT) ratings using
[arena-rank](https://github.com/lmarena/arena-rank), separately for each batch.

| File | Narratives | Metrics |
| --- | --- | --- |
| `rag-bt-scores-batch1.tsv` | 17 | `bt_score` with 95% confidence intervals |
| `rag-bt-scores-batch2.tsv` | 25 | `bt_score` with 95% confidence intervals |
| `rag-sxs-counts-batch1.tsv` | 17 | `wins`, `ties`, and `losses` |
| `rag-sxs-counts-batch2.tsv` | 25 | `wins`, `ties`, and `losses` |

| Column | Meaning |
| --- | --- |
| `bt_score` | Bradley–Terry rating fitted from human pairwise preferences. |
| `ci_lower`, `ci_upper` | Lower and upper bounds of the rating's 95% confidence interval. |
| `wins` | Number of battles in which the system's answer was preferred. |
| `ties` | Number of battles judged both good or both bad. |
| `losses` | Number of battles in which the other system's answer was preferred. |

Higher BT scores are better. Compare scores within the same batch. BT files
contain only `all` rows because ratings are fitted across the batch.
Confidence intervals use arena-rank's sandwich estimator at the judgment level.

Each preference contributes one win to the preferred system and one loss to
its opponent. Both `both_good` and `both_bad` contribute one tie to each
system. `wins + ties + losses` is the number of battles involving that system.

We selected the top-2 priority runs for side-by-side assessment, so the BT and
side-by-side count files list only those two runs, while the rubric and nugget
files list all of your evaluated runs.

## Rubric Evaluation: Vital-Strict and All-Strict Scores

Batch 1 measures how well the generated answer satisfies the human-intuition
rubric criteria that NIST assessors created before conducting their Batch-1
side-by-side assessments. Batch 2 measures the proportion of answer nuggets
covered by the generated answer.

A **nugget** is a piece of information—a distinct claim or fact—that we expect
a high-quality RAG answer to the narrative to contain, following the
[TREC nugget evaluation methodology](https://arxiv.org/abs/2411.09607).
Vital nuggets are essential to a good answer; okay nuggets add useful but
nonessential information. We measure whether generated answers fully
support each nugget. Rubric and nugget assignments (is each item supported
by the answer?) are made automatically for all three collections; Batch 1
uses the human-intuition rubric items in place of nuggets.

| File | Narratives | Rubric or nugget source |
| --- | --- | --- |
| `rag-rubric-scores-batch1-human.tsv` | 17 | NIST's human-intuition rubrics with automatic rubric assignment |
| `rag-nugget-scores-batch2-manual.tsv` | 25 | NIST's human-authored nugget rubrics with automatic nugget assignment |
| `rag-nugget-scores-batch2-automatic.tsv` | 25 | Nuggets automatically generated by RAGDoll using the [AutoNuggetizer framework](https://dl.acm.org/doi/abs/10.1145/3726302.3730090), with automatic nugget assignment |

| Column | Meaning |
| --- | --- |
| `vital_strict` | Number of fully supported vital items / total number of vital items for the narrative. |
| `all_strict` | Number of fully supported vital and okay items / total number of vital and okay items for the narrative. |

Higher scores are better. Only full support earns credit; partial support earns
zero. A narrative with a zero denominator (e.g. no vital items) scores zero. `vital_strict` uses vital items only. `all_strict` weights vital
and okay items equally. Assignments use GPT-6.1 Sol at medium reasoning for
all three collections.

For narrative $t$, let $N_t$ be its rubric or nugget items, $V_t$ its vital
items, and $C_t$ the items fully supported by the generated answer:

$$
\begin{aligned}
{\text{vital strict}}_{t} &= \frac{|C_t \cap V_t|}{|V_t|} \\
{\text{all strict}}_{t} &= \frac{|C_t|}{|N_t|}
\end{aligned}
$$

We provide `compute_rubric_scores.py` as a scoring reference. Rubric and nugget
assignments are not yet available for distribution.

```bash
python3 compute_rubric_scores.py assignments.jsonl \
  --run RUN_ID -q -c --topics batch1-topics.txt
```

- `--run`: required; select one of your runs by its `run_id`.
- `--topics`: use `batch1-topics.txt` (17 narratives) or `batch2-topics.txt`
  (25 narratives, for either manual or automatic nuggets).
- `-c`: include all listed narratives in the average, scoring missing ones zero.
- `-q`: print per-narrative scores as well as the `all` averages.

Use one collection's assignments at a time. The assignments JSONL input follows
the RAGDoll output format, containing one record per run and narrative,
with `run_id`, `qid`, and a `nuggets` list
containing all rubric items for that narrative.
Each item has `text`, `importance` (`vital` or `okay`), and `assignment`
(`support`, `partial_support`, or `not_support`):

```json
{"run_id":"example-run","qid":"rag2026-11","nuggets":[{"text":"Example rubric item.","importance":"vital","assignment":"support"}]}
```

Output is printed to the terminal in TREC format:
`metric<TAB>narrative-id<TAB>value`, for `vital_strict` and `all_strict`.

## Reference Statistics

- **`all`** is an equally weighted narrative average for rubric/nugget scores:
  17 narratives for Batch 1 and 25 for either Batch-2 nugget file.
- For BT files, **`all`** is the system's Bradley–Terry rating from a single
  fit using all human pairwise judgments across the batch's evaluated
  narratives: 17 for Batch 1 or 25 for Batch 2. Each batch is fitted separately;
  the rating is not an average of per-narrative BT scores.
- For side-by-side count files, **`all`** is the sum of wins, ties, and losses
  across narratives.
- **`_min`, `_max`, `_median`** are based on all submissions evaluated for that
  metric, with each run weighted equally. In `all` rows, they summarize the
  runs' overall scores. They are computed from the published rounded scores;
  your team's files retain the global statistics across all evaluated runs.
