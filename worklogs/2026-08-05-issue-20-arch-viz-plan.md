## Decision 1 — agentic/code split granularity (issue's open question)

**Decision: three classes (`llm`, `code`, `llm+code`), *derived* from change #1's data — a stage is agentic iff it declares a `prompt` ref, code iff it declares a `code` ref, both iff both. No separate hand-authored `agentic:` flag.**

Justification: the honest answer is not derivable from `kind`, and the issue's framing ("is the split per-stage-as-drawn?") has different answers per system. facet_rag's `SEARCH` box *is* one loop step whose body (`loop.py:229-262`) makes the `ORCHESTRATOR_QUERY_PROMPT` call **and** executes `run_search_tool` — the model call is literally inside the stage. aus_agent's `SEARCH` (`tools/search.py::execute_full_text_search`) and ali_deepresearch's `TOOL_CALL` (`react_agent.py::_handle_tool_call`) are pure code; their model turn is a *different drawn box* (`REASON/COMMIT`, `THINK`). So a per-kind rule would be wrong for facet_rag, and a per-stage hand-authored flag would be a second source of truth that rots. Deriving the class from the presence of a resolved prompt/code ref makes the badge unfalsifiable: a box can only claim "LLM" if the panel can show you the prompt constant it calls, and only claim "code" if the panel can name the function — the badge and the detail panel cannot disagree, and adding a stage without detail data yields no badge rather than a wrong one.

Consequence to flag to the user (deviation from the issue's literal test case 2): `FORMAT` comes out **`llm+code`**, not code-only, for facet_rag and ali_deepresearch — `format_answer` (`ali_deepresearch/answer_format.py:148-173`) really does make a `FORMAT_ANSWER_PROMPT` call when `llm` is passed, and facet_rag passes it by default (`pipeline.py:224`, `format_llm: bool = True`). `SAVE`, `MAP CITES`, `STAGE` stay pure code. If the user insists on the issue's literal assertion, the one-line alternative is to omit the `prompt` ref on `FORMAT` — but then the panel can't show the formatting prompt, which change #1 exists to do. Plan proceeds with the honest classification and records the deviation in the worklog + an issue comment.

## Decision 2 — parallel-across-facets vs sequential-within-facet

**Decision: two orthogonal visual channels. Sequential repetition keeps the dashed back-edge (moved below the row). Concurrency is drawn as *depth*: when the loop stage declares `"parallel_over": "facet"`, the bounding rect is rendered as a stack of three offset rects (two ghost copies behind at +6/+12 px, reduced opacity) and its label reads `FACET LOOP × facet (concurrent)`.**

Justification: the two repetitions are orthogonal facts about the same span — one thread revising its own search (the arrow, `loop.py:221` `for _ in range(cap)`) and N independent threads over facets (`pipeline.py:186-192`, `ThreadPoolExecutor(max_workers=max(1, len(facets)))`). Encoding both as arrows would need a second arrow with no distinguishable semantics; encoding concurrency as depth uses a channel the diagram doesn't otherwise use, reads instantly as "many copies of this box," and costs two extra `<rect>` elements. `aus_agent`'s `TURN LOOP` and `ali_deepresearch`'s `ReAct LOOP` declare no `parallel_over` and get a single flat rect, so the distinction is visible by comparison within the same page.

## Step 1 — data model in `gen_arch_viz.py` (lands first; everything else consumes it)

### 1a. Ref resolvers (new, ~45 lines, placed after `_read_engines`, before `build_model`)

Refs are `<path-relative-to-src>[::<Symbol>[.<attr>]]`, e.g. `systems/facet_rag/prompts.py::CURATOR_PROMPT`, `tools/search_tool.py::run_search_tool`, `systems/aus_agent/prompts/system/default.md` (no `::` -> whole file read).

```python
SRC = REPO_ROOT / "src"

def _module_value(ref: str) -> Any | None:      # literal RHS, or None if not a literal
def _symbol_exists(ref: str) -> bool            # module-level Name/FunctionDef/ClassDef, or Class.method (one dot)
def _prompt_text(ref: str) -> str               # literal_eval for ::CONST, read_text() for a bare path
```

All three `raise SystemExit(f"gen_arch_viz: unresolvable ref {ref!r}")` on a miss, so a renamed prompt/function fails generation loudly (and therefore fails `--check`, the pre-commit hook, and CI) instead of silently showing a stale location. No line numbers are recorded anywhere: a line number would make `docs/architecture.html` churn on every unrelated edit above a function and turn the freshness hook into noise.

### 1b. New optional stage keys (all authored in `STAGE_REGISTRY`)

- `prompt`: `list[str]` of prompt refs
- `code`: `list[str]` of code refs
- `tools`: `list[{"name": str, "ref": str}]` — native tool-calling stages
- `engines`: `{"mandatory": <ref to a tuple const>, "optional": <ref>}` — facet_rag-style
- `tools_note`: one-line string (why native tool-calling isn't used, where the config comes from)
- `parallel_over`: string, loop stages only

### 1c. Normalization in `build_model()`

- Prompt texts are **deduped into a top-level `model["prompts"]: {ref: text}`**; stages carry refs only (aus's 15.4 KB system prompt is referenced by both `REASON/COMMIT` and `FINAL PROSE` and must not be inlined twice).
- `tools` + `engines` both normalize into one model key `stage["tools"] = [{"name", "desc", "ref", "group"}]` where `group ∈ {"tool", "mandatory engine", "optional engine"}`:
  - native tools: `desc` = the literal dict's `"description"` when `_module_value` returns a dict (works for `GET_DOCUMENTS_TOOL`, `COMMIT_CONTEXT_TOOL`), and generation **asserts `lit["name"] == declared name`** so a rename is caught; for non-literal RHS (`SEARCH_TOOL_DEF = build_search_tool_def([...])`) `desc` is `""` and the panel prints `schema built at runtime — see <ref>`.
  - engines: names from `literal_eval` of `MANDATORY_ENGINES`/`BOOLEAN_ENGINES`, `desc` left empty — the JS looks the blurb up in the already-present `MODEL.engines` (populated by `_read_engines`, `ENGINE_INFO` in `tools/search_tool.py:46-78`) so no blurb text is duplicated in the JSON.
- `stage["run"] = "llm" | "code" | "llm+code" | None` derived per Decision 1.
- Determinism: iterate declared lists in declaration order, never over a `set` (same discipline as the comment at lines 223–225). `--check` stays byte-stable.

### 1d. Fix the two latent blockers

`_arch_stages_override`: keep values as-is (drop `str(v)`), validate with `json.dumps(x)` and skip the override with a printed warning if it isn't JSON-serializable. Widen the `STAGE_REGISTRY` annotation to `dict[str, list[dict[str, Any]]]`.

## Step 3 — change #1 + #4: click-to-open detail panel

**Click, not hover** — prompts are 1–15 KB of multi-line text; a `mousemove`-anchored tooltip can't be scrolled or text-selected, and the existing `#tip` is `pointer-events: none`. Keep the current `note` tooltip on hover as the cheap glance; add click for depth.

- HTML: one `<aside id="detail" hidden>` inside `#wrap` (after `#tip`), with a `<button id="detail-close">`.
- CSS: fixed right-side panel, `overflow:auto`, monospace `<pre>` blocks for prompt text.
- JS `showDetail(sys, stg)`: header (label/kind/run badge), `note`, PROMPT section (ref + `<pre>` filled via `textContent` from `MODEL.prompts[ref]` — never `innerHTML`), CODE section (refs), TOOLS/ENGINES section (grouped, engine blurbs looked up in `MODEL.engines`), `tools_note`, plus the enclosing loop's tools under `available in <LOOP LABEL>`.
- Wiring: `tabindex=0`, `role="button"`, `aria-label`, `click` + `keydown` Enter/Space on each stage `<g>`. `Escape` closes the panel first if open, else falls back to today's back-to-overview behavior. `route()` closes the panel on redraw.

#4 needs no separate rendering work — it is the TOOLS section of this same panel.
